# Agent Note: 升级基础镜像到 Debian 13 trixie / glibc 2.41

Status: implemented

## Problem

用户要求把镜像的 glibc 从 2.36 升级到 2.41。当前 `python:3.13.17-slim-bookworm` 及 Node / Rust 来源阶段都是 Debian 12 bookworm（glibc 2.36）；在 bookworm 上手工替换 glibc 会破坏 apt、`libc6-dev` 和工具链 ABI，不是可维护的升级方式。

## Decision

- [Dockerfile](../../../../Dockerfile) 最终 base 改为 `python:3.13.17-slim-trixie`，Node / Rust 来源阶段同步改为 `node:24.22.1-trixie-slim` / `rust:1.98.1-slim-trixie`，三者都基于 Debian 13 trixie，glibc 2.41。
- 保留精确版本 pin：Python 3.13.17、Node 24.22.1、Rust 1.98.1，避免浮动标签导致重建漂移。
- 构建期和 [完整镜像冒烟](../../../../tests/image-smoke.sh) 增加 `getconf GNU_LIBC_VERSION` 必须等于 `glibc 2.41` 的断言；[配置回归](../../../../tests/config.test.mjs) 禁止 base 回退到 bookworm，并校验三个精确 trixie 标签。
- [README](../../../../README.md) 和 [维护者文档](../../../../docs/maintainer.md) 的 Debian / glibc / base 说明同步更新。
- [轻量入口测试镜像](../../../../tests/Dockerfile) 同步使用 `node:24.22.1-trixie-slim`，避免测试镜像和正式镜像跨发行版。

## Alternatives considered

- 在 Debian 12 bookworm 上单独安装或编译 glibc 2.41：版本看似达标，但会替换系统 libc、破坏 apt 和 `libc6-dev`，且所有动态链接工具链都需要重编译；不可维护。
- 只升级 Python base 到 trixie，Node / Rust 仍用 bookworm：Python 镜像的 glibc 2.41 高于来源阶段的 2.36，跨阶段 COPY 会带入旧 glibc 依赖；三者必须同步升级。
- 使用 Ubuntu 25.04 / 其他发行版：也能提供 glibc 2.41，但会改变 apt 包名、工具链路径和现有 Debian 兼容性，且不是当前镜像的发行版基线；trixie 是 Debian 12 的直接后继稳定版，迁移面最小。

## Testing

- 已核实 Docker Hub 存在 `python:3.13.17-slim-trixie`、`node:24.22.1-trixie-slim`、`rust:1.98.1-slim-trixie` 的 amd64 / arm64 manifest。
- 解包 `python:3.13.17-slim-trixie` 的 amd64 rootfs 验证：Debian 13.7 trixie，`getconf GNU_LIBC_VERSION` 为 `glibc 2.41`，`ldd --version` 为 `ldd (Debian GLIBC 2.41-12+deb13u4) 2.41`，Python 为 3.13.17。
- 解包 Node / Rust trixie 来源镜像均验证 `glibc 2.41`；Node 的 `/usr/local/bin/node`、`/opt/yarn-*` 和 Rust 的 `/usr/local/{rustup,cargo}` 路径存在。
- 本地 Node 测试、Shell 语法、ShellCheck 和笔记门禁通过；真实 Docker 构建及双架构容器验收由 GitHub Actions 完成。

## Consequences

- 镜像基础从 Debian 12 升到 Debian 13，系统库、apt 包版本和 glibc ABI 都变化；依赖旧版 Debian 系统库或旧 glibc 的项目需要重新验证。
- 旧镜像 / 旧容器不会自动升级；必须重新构建镜像并重建容器。
- 由于三者都是 trixie，Node / Rust 跨阶段 COPY 的 glibc 兼容性保持一致；后续升级任一来源镜像时必须继续保持 trixie（glibc 2.41）基线。

## Related notes audit

[Python 3.13 升级](../feature/2026-10-26-python-313.md) 中“使用 trixie”被当时的 bookworm 基线拒绝；本决定在用户明确要求 glibc 2.41 后取代该选择，Python 3.13.17 及运行时布局保持不变。
