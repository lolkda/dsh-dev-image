# Agent Note: 镜像全局 Frida CLI

Status: implemented

## Problem

镜像需要提供可从任意目录调用的 frida 及配套命令，不能依赖用户安装或激活环境。

## Decision

固定 frida 17.23.1 与 frida-tools 14.11.0，使用镜像 Python 在 /opt/frida 创建独立 venv，通过 PyPI 安装。将 venv 的 frida* 可执行入口链接到已有 PATH 中的 /usr/local/bin，不改入口、用户 PATH 或工作目录。不安装或启动目标设备的 frida-server。

## Alternatives considered

全局 pip 安装与现有 uv 安装方式一致、改动最少，但 Frida 的多项 Python 依赖会和用户项目共用系统环境；独立 venv 保持 CLI 依赖隔离。仅安装 frida 包可提供绑定，但不会提供用户需要的 frida-tools 命令。

## Testing

固定依赖在本地独立 venv 安装成功并通过 pip check。真实 CLI 经临时 PATH 目录的符号链接，在 /tmp 和 / 中以普通 shell、登录 shell和无 shell 的进程调用运行：frida --version 返回 17.23.1，frida-ps/frida-trace/frida-ls-devices --help 成功。

使用 FRIDA_TEST_BIN 指定已安装 venv 的 bin 目录运行全部 Node 测试：130 项通过，1 项已有非 root 测试跳过。构建期双 shell、容器双 shell 与裸 docker exec 的冒烟均包含 Frida 检查；当前无 Docker CLI，未执行完整镜像构建或容器验收。既有 apktool 改动保留并通过回归。

## Consequences

无需激活 venv 即可全局调用 CLI，依赖不污染系统 Python。下载依赖 PyPI；次级依赖未完全锁定。客户端 CLI 可用不代表设备已连接或允许注入；目标端 server 需匹配客户端核心版本和目标架构。用户需要重新构建镜像和容器以获得工具。
