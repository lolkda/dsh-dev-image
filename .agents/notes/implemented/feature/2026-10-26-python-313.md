# Agent Note: 升级到 Python 3.13

Status: implemented

## Problem

镜像 base 仍是 `python:3.12-slim-bookworm`，Python 停在 3.12.x。用户要求把项目镜像升级到 Python 3.13，同时不能破坏现有 Frida、uv、pip、登录 Shell 和用户级 CLI 的持久化路径。

## Decision

- [Dockerfile](../../../../Dockerfile) 的最终镜像 base 改为 `python:3.13.17-slim-bookworm`，继续使用 Debian 12 bookworm 与 glibc 2.36，保持和 Node / Rust 来源阶段的 glibc 兼容性。
- 使用精确补丁标签而不是浮动的 `python:3.13-slim-bookworm`，避免重建时随 Docker Hub 补丁漂移。Python 3.13.17 是 2026-10 可用的 3.13 bookworm 补丁版本。
- 构建期两条 Shell 的冒烟都断言 `python -V` 为 `Python 3.13.17`，并实际导入 `bz2`、`ctypes`、`lzma`、`sqlite3`、`ssl`、`uuid`，确保 base 的系统库没有在升级中丢失。
- [完整镜像冒烟](../../../../tests/image-smoke.sh) 同样断言精确版本和上述原生模块，避免只验证镜像层而漏掉容器运行时的动态库问题。
- [README](../../../../README.md) 的版本表、base 选择说明和 `pip install --user` 的 `site-packages` 路径同步改为 3.13.17 / `python3.13`。
- [配置回归](../../../../tests/config.test.mjs) 固定 Python 基础镜像必须是精确的 bookworm 标签、主次版本为 3.13、补丁不低于 3.13.17，并检查构建期与镜像冒烟都没有漏掉版本断言。

## Alternatives considered

- 继续使用 `python:3.13-slim-bookworm` 浮动标签：改动最小，但无法审计实际补丁版本，也无法阻止下一次构建悄悄换版本；与现有 Node 基础镜像的精确固定策略不一致。
- 使用 `python:3.13.17-trixie`：Python 版本相同，但 trixie 的 glibc 2.41 高于 Node / Rust 来源阶段的 2.36，跨阶段 COPY 会带来运行时兼容风险。
- 保留 Debian 裸 base 并自行编译 Python 3.13：可以把 Debian 版本固定得更死，但会重复官方镜像已经处理的 `.so` 依赖、`ldconfig` 和构建校验，维护成本更高。
- 继续留在 Python 3.12：最保守，但不满足本次升级目标，也会继续积累与 3.13 生态的差距。

## Verification results

- 已核实 Docker Hub 存在 `python:3.13.17-slim-bookworm`，amd64 / arm64 均有 manifest；该镜像仍基于 bookworm，glibc 为 2.36。
- 已核实 `frida==17.23.1` 提供 `cp37-abi3` manylinux wheel，`frida-tools==14.11.0` 的 `websockets<14` 依赖在 `websockets==13.1` 提供 cp313 wheel；`uv==0.12.17` 声明支持 Python 3.13。
- 在临时 Python 3.13.15 venv 中实际安装 `frida==17.23.1` / `frida-tools==14.11.0`，`pip check` 通过，`frida --version` 返回 17.23.1，`frida-ps` / `frida-trace` / `frida-ls-devices` 的 `--help` 均可执行；同时验证 `bz2`、`ctypes`、`lzma`、`sqlite3`、`ssl`、`uuid` 可导入。该环境低于镜像目标的 3.13.17 补丁，但 wheel ABI 与依赖解析路径相同。
- `node --test tests/config.test.mjs` 57 项全部通过；`node --test tests/*.test.mjs` 166 项中 164 通过、2 项环境跳过、0 失败；`bash -n` 与 `shellcheck` 检查入口和冒烟脚本通过。
- 当前环境没有 Docker CLI，未实际构建镜像、运行容器冒烟或验证 amd64 / arm64 分支；这些仍需由 Docker CI 完成，不能用静态测试替代。

## Consequences

- 用户级 `pip install --user` 的安装目录从 `lib/python3.12/site-packages` 变为 `lib/python3.13/site-packages`。已有 Python CLI 和虚拟环境应在重建容器后重新安装；入口不会自动迁移 `.local` 下的旧包。
- Python 3.13 是次版本升级，带原生扩展的项目依赖需要重新构建 wheel 或虚拟环境；Frida 的独立 `/opt/frida` venv 会在下次镜像构建时按 3.13 重建。
- 升级后的运行时位于镜像层，已有容器只 `restart` 不会获得 Python 3.13，必须重新构建镜像并重新创建容器。
- 后续跟进 Python 3.13 安全补丁时，需要显式修改 Dockerfile、构建冒烟断言、README 和配置回归中的版本下限。
