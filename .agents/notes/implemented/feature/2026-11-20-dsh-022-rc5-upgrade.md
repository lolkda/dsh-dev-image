# Agent Note: 升级 DSH 到 0.2.2-rc.5

Status: implemented

## Problem

镜像的 `DSH_VERSION` 固定在 `0.2.2-rc.2`，需要升级到 npm 已发布的 `0.2.2-rc.5`。镜像还维护 `dsh-subagent` 的 child-setup v1 宿主补丁，必须用真实 rc.5 tarball 重新确认补丁字节和基线，不能只改 `ARG DSH_VERSION`。

## Decision

- [Dockerfile](../../../../Dockerfile) 的 `ARG DSH_VERSION` 固定为 `0.2.2-rc.5`。
- [README](../../../../README.md) 和[维护者文档](../../../../docs/maintainer.md)中的 DSH 版本同步更新。
- 以 npm 发布的 `@deepseek-ai/dsh-subagent@0.2.2-rc.5` 为真实基线重新校验 [child-setup 补丁](../../../../patches/dsh-subagent-child-setup-v1.patch)；补丁仍可零模糊精确应用，只更新[基线版本号和哈希](../../../../patches/dsh-subagent-child-setup-v1.baseline.json)。
- 不改变 child-setup 协议、镜像入口、默认插件或运行时架构。

## Alternatives considered

- 只升级 `ARG DSH_VERSION`：无法证明宿主补丁仍适用于 rc.5，构建可能在补丁阶段失败或留下错误基线。
- 删除 child-setup 补丁：会丢失具体 Team Agent preset 的创建前应用和冷恢复能力。
- 允许 patch 模糊匹配或忽略失败：会掩盖上游字节变化，现有回归明确拒绝这种降级。
- 使用 `next` / `latest`：镜像不可复现。

## Testing

- `node --test tests/subagent-patch.test.mjs`：15 项通过；真实 rc.5 tarball 零模糊精确应用，前后 SHA-256 匹配。
- `node --test tests/*.test.mjs`：184 项，182 通过、0 失败、2 项既有环境跳过。
- 隔离安装 `@deepseek-ai/dsh@0.2.2-rc.5` 并应用补丁后，`dsh --version` 为 `0.2.2-rc.5`，`dsh --help` 正常。
- `bash tests/subagent-runtime.sh`：在 rc.5 + `@lolkda/dsh-agent-team-model-pin@1.8.4` 上 8 项真实 Team preset 集成测试全部通过。
- 当前容器没有 Docker，真实多架构镜像构建、容器权限验收和 `tests/image-smoke.sh` 仍由既有 Docker CI 完成。

## Consequences

- 已运行容器不会自动升级，必须重建或拉取新镜像后重建容器；单纯 restart 不会生效。
- 后续每次 DSH 升级都必须重新核对 child-setup 补丁的真实 npm 字节、基线哈希和 Team preset 集成测试。
