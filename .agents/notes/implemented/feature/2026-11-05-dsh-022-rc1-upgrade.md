# Agent Note: 升级 DSH 到 0.2.2-rc.1

Status: implemented

## Problem

镜像的 `DSH_VERSION` 仍固定在 `0.2.1-rc.2`，本次要求升级到 `0.2.2-rc.1`。目标 DSH 包依赖 `@deepseek-ai/dsh-subagent@0.2.2-rc.1`；该版本调整了 service 初始化结构，旧的 child-setup v1 补丁有五个 hunk 无法精确应用。只修改 `ARG DSH_VERSION` 会在镜像构建的宿主补丁阶段失败。

## Decision

- [Dockerfile](../../../../Dockerfile) 的 `ARG DSH_VERSION` 固定为 `0.2.2-rc.1`，继续使用精确版本而不是 `next` 或 `latest`。
- [README](../../../../README.md) 和[维护者文档](../../../../docs/maintainer.md)中的 DSH 版本同步更新。
- 以 npm 发布的 `@deepseek-ai/dsh-subagent@0.2.2-rc.1` 为真实基线，重新生成 [child-setup 补丁](../../../../patches/dsh-subagent-child-setup-v1.patch)。保留 cold-resume 的持久化 preset 恢复、`childSetupVersion=1`、`registerChildSetup`、同步 commit 校验及发布前 setup 顺序。
- 补丁适配新的 `Service.init` 投影注册位置；[基线哈希](../../../../patches/dsh-subagent-child-setup-v1.baseline.json)同步更新，回归测试继续要求 `patch --fuzz=0` 精确应用且无偏移。
- 本次不改变 child-setup 协议本身，也不改变镜像的默认插件、入口或架构边界。

## Alternatives considered

- 只升级 `ARG DSH_VERSION`：目标包的上下文已变化，构建会在补丁阶段失败。
- 删除 child-setup 补丁：会丢失 Team preset 的具体 Agent 预设保存/冷恢复能力，属于功能回退。
- 允许 `patch` 模糊匹配、偏移或忽略失败：会掩盖上游字节变化，现有回归明确拒绝这种降级。
- 使用 `next` 或 `latest` dist-tag：构建结果会随 registry 漂移，不符合镜像的可复现性要求。

## Consequences

- 已运行容器不会自动升级，必须重新构建或拉取新镜像后重建容器，单纯 `restart` 不会生效。
- child-setup 补丁仍是镜像维护的局部补丁；后续每次 DSH 升级都必须重新核对真实 npm 字节、基线哈希和 Team preset 集成测试。
- DSH 0.2.2 移除了 `installModelSelection(agentCtx, ModelSelectionRef)`。`@lolkda/dsh-agent-team-model-pin@1.5.1` 的模型钉半边不兼容，需要插件侧适配新的 `AgentModel.select()`/`model/selection` 流程；本镜像默认不安装该插件，Team preset 创建与恢复不受影响，但使用该插件模型钉的 profile 暂时不能升级此镜像版本。
- 目标版本已通过本地包级安装与补丁验证，但发布门禁仍取决于 Docker CI 的双架构构建和完整镜像冒烟。
